# 缓存写入计费

价格由本地 `model_endpoint_map.json` 的 `pricing` 配置决定，实际模型价目不随代码提交。

| 字段 | 含义 |
| --- | --- |
| `cached_input` | 缓存命中单价，缺省按普通输入计费 |
| `cached_input_explicit` | 可选的显式缓存命中单价，按实际上游请求的缓存标记选择 |
| `cache_write` | 缓存写入完整单价，Anthropic 对应默认五分钟缓存 |
| `cache_write_1h` | 一小时写入完整单价，缺省沿用默认写入价 |
| `input_tiers` | 单次请求的输入长度档位，`min_input_tokens` 为包含边界的下限 |

写入完整单价包含普通输入部分。缺省表示不额外收费，写入 Token 仍按普通输入计费；零表示写入 Token 本身免费。管理页支持编辑默认及一小时写入价，保存时保留 JSON 中的其他计费字段。

总输入量包含普通输入、缓存读取和缓存写入。三部分按各自单价计费，一小时写入量是总写入量的子集。`cache_write_cost` 为写入完整费用，`cache_write_extra_cost` 为它相对普通输入的差额；该差额仅用于展示，不再次加入总价。

支持 OpenAI/兼容 Chat 的缓存写入明细，以及 Anthropic 的总写入量和两个 TTL 明细。仅使用上游实际报告的写入量，不把所有未命中输入都视为写入。兼容接口转换会保留相关用量。

SQLite 详情、列表、用量汇总、CSV 和多来源合计包含写入费用。未配置价格时仍记录写入量。旧账单金额不变，只读价格对比可从原始 usage 恢复历史写入量，逐请求选择长度档位。

不包含按小时的缓存存储费、峰谷自动切换、独立工具费用、区域或服务等级溢价。
