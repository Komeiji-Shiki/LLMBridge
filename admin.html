Token 预算适用于 Gemini 2.5/旧模型、Anthropic/OpenRouter；强度等级（low/medium/high）适用于 OpenAI 兼容上游和 Gemini 3（映射为 thinkingLevel）

不同模型最大输出Token不同
不同API返回cached_tokens的方式不同：
• 关闭：直接使用prompt_tokens，不处理缓存
• 正向：某些反代把cached单独返回，需要相加得到总输入
• 反向：DeepSeek官方API中prompt_tokens已包含全部，cached只是记录
上游usage不可信时（如输入恒为个位数的反代），选择“本地Tokenizer”用tiktoken等本地分词器估算输入/输出token
控制发给下游客户端的 usage.completion_tokens 口径（成本与监控统计永远按真实总输出计算，不受本项影响）：
• 勾选（默认）：completion_tokens = 正文 + 思考，即总输出，与多数API的口径一致
• 不勾选：completion_tokens 只算正文，思考量单独放在 completion_tokens_details.reasoning_tokens
两种口径下 reasoning_tokens 都会保留，total_tokens 都等于「输入 + 正文 + 思考」的真实总量。
部分上游与中转把思考单列（total = prompt + completion + reasoning），不开本项时客户端读到的输出会明显偏小； 已经包含思考的标准 OpenAI 响应不会重复相加（按 total 算术关系自动识别）。

为最后一条assistant消息添加 "partial": true 参数（适用于Kimi K2等模型的预填充续写）
在此输入的内容将作为 {"role": "assistant", "content": "..."} 追加到消息列表末尾。 常用于跳过模型思考阶段或预设回答开头。留空则不启用。
